# Frozen app-server client contract

## Exact upstream target

The baseline is the non-experimental schema generated by official
`@openai/codex`/`codex-cli` version `0.147.0`. The official source tag
`rust-v0.147.0` is tag object
`3ed6f04f6bf8b7c46299d1cb1ff99c74ce21a51d` and peels to source commit
`be6e8eac029b183056b7e4402879f15d2c85f61b`. The observed wrapper SHA-256 is
`134063e133f0b4244fa3b251acf973d4fe4b4aeeacbdc135211bf480f59f1477`.
The observed `aarch64-apple-darwin` native executable SHA-256 is
`19c4f144c5226a9f17c58e6f0fa854843b0f77a6eb420f40e2745a12f10f5d37`.

The complete 285-file generated tree is retained under
`protocol/upstream/0.147.0`. Its byte tree root is
`eb325d394d19f2f8d133203885b3d1c2f74dbc5a176f22078a4f99aae5926faa`.
`protocol/upstream-manifest.json` records every relative path, size, and digest.
This is provenance evidence, not a claim that every upstream method is public.
The selected-surface root is
`9a773e75f2e5aa827b4cc711345bd9ca1bc2a037f19d114284a04f306097a42f`.
The exact public-API manifest SHA-256 is
`11e02c9c460821ebd5dd08f80b6544eb45b2217a53b90918ca472c26d14e1a21`.
The maintained checker pins those roots plus the version, tag object, peeled
commit, generation mode, wrapper/native hashes, schema count, byte count, and
schema root; changing a self-consistent manifest alone therefore fails CI.

The retained tree and all selected unions are checked without invoking the
binary by:

## Public API contract

The eventual root import is `codex_app_server_client`. It exports only typed
configuration, compatibility, lifecycle, request, event, callback, and error
objects. Raw JSON-RPC method names, arbitrary payload dictionaries, request-ID
allocation, framing, and byte-channel writes remain private.

The public lifecycle is one explicit configuration into one client owner:

```python
binary = resolve_codex_binary()
compatibility = inspect_compatibility(binary)
transport = StdioTransport(binary)
client = await AppServerClient.connect(transport, compatibility)
try:
    session = await client.initialize(ClientIdentity(name="host", version="1"))
finally:
    await client.close()
```

This example illustrates the frozen signatures only; Block 2 implements no
Python behavior. `protocol/public-api.json` is normative. It records both
compatibility functions, every lifecycle and session method name and exact
signature, every top-level request/result schema mapping, all notification and
callback model tags, every capability-enum member, transport and ownership
signatures, configuration models, model-generation rules, root-export rules,
and every concrete error subclass. Exactly one owner closes or replaces a
transport.

`AppServerSession` exposes typed operations corresponding only to the eight
`public_typed` request methods in `protocol/supported-surface.json`. Parameters
and results are named frozen models derived from the matching official schema
definitions. A caller cannot pass an arbitrary method or untyped payload.
Every transitively referenced official definition is generated by the exact
closed rule in `public-api.json`; unequal same-name schemas fail rather than
being renamed or silently merged.

`AppServerSession.capabilities` accepts only closed request, notification,
callback, and transport enums. Availability requires both presence in the
accepted schema root and the applicable compatibility/session precondition.
Initialization declares `experimentalApi=false`, no MCP extensions, no
attestation request, and opts out of every known unselected notification.

Events form a closed tagged union for the selected server notifications.
Callbacks form a closed tagged union for command approval, file-change
approval, and user-input requests. The package supplies the envelope and
exactly-once response mechanism but never chooses an approval or product
action. Unknown or unselected inbound requests are rejected with a typed
unsupported-message error; there is no raw fallback.

The non-experimental `0.147.0` generation includes the selected plan-delta and
user-input files even though their upstream schema descriptions use the word
experimental. Their presence in the non-experimental tree plus their explicit
Block 2 selection governs this frozen contract; it does not admit any other
experimental method. Removing them requires a reviewed contract-root change.

`protocol/supported-surface.json` records a neutral necessity statement for
each selected request, notification, callback, and transport. The selected set
is eight request methods, fifteen notification methods, three callback methods,
and three transports. The maintained checker requires a one-to-one match among
those selections, the necessity map, the public operation/model maps, and all
four closed capability enums.

## Source adaptation boundary

Only the official CLI, its generated schemas, package metadata, and official
source tag were inspected. No existing client implementation or downstream
repository was inspected, imported, executed, or copied. Consequently this
contract classifies no prior client API or product behavior for reuse: all
future implementation is owned here and derived from the official protocol
plus the neutral lifecycle constraints in this document.

## Error contract

Public failures are the exact discriminating subclasses of
`AppServerClientError` listed in `protocol/public-api.json`:

- resolution, version, schema-load, schema-root, and unsupported-feature
  compatibility errors;
- framing, validation, request-bound, message-size, correlation, and remote
  JSON-RPC errors;
- transport-start, transport-closed, ownership, and cleanup errors;
- initialization and session-state errors;
- timeout, cancellation, callback-capacity, and disconnect errors; and
- stale-generation and restart errors.

Errors may contain method, request ID, generation, limits, error code, and
content-free diagnostics. They do not log prompts, response content, secrets,
or consumer identifiers.

## Compatibility rule

The package is compatible only when all of the following are exact:

1. the resolved executable is unambiguous and reports Codex `0.147.0`;
2. generated or retained schemas produce the accepted semantic root defined by
   Block 3 and contain every selected definition;
3. selected methods preserve their request, response, notification, and
   callback schemas; and
4. the package's frozen selected-surface root matches the installed package.

Unknown required features, missing definitions, malformed schemas, changed
semantic roots, and version drift fail before a transport starts. Patch-level
upstream changes are not assumed compatible. Any accepted upstream change
requires a reviewed manifest and schema update. Additive upstream surface does
not automatically widen the package API.

## Deterministic update procedure

1. Select one official Codex release and resolve its tag object and peeled
   source commit from `https://github.com/openai/codex`.
2. Hash the installed wrapper and platform-native executable and confirm both
   report the selected version.
3. Run `codex app-server generate-json-schema --out <disposable-dir>` exactly
   once without `--experimental`.
4. Validate every output as JSON, calculate the sorted byte-tree root with
   `scripts/schema_tree.py`, and compare it with a second calculation only if
   investigating nondeterminism.
5. Review the selected surface against the generated unions. Preserve the
   existing public surface unless an independently admitted capability requires
   change; never auto-export new upstream methods.
6. Replace the retained schema tree and regenerate `upstream-manifest.json` in
   one candidate. Block 3 then updates semantic compatibility fixtures and
   tests; later Blocks update only their owned typed models and proof.
7. Treat any selected schema change as at least a package minor-version review
   and any incompatible public model change as a major-version review. This
   repository still does not publish or release without separate authority.

## Explicit exclusions

WebSocket, public listeners, remote proxying, experimental APIs, raw RPC,
authentication/account management, configuration and filesystem mutation,
plugins/marketplaces, MCP administration, realtime media, remote control,
shell-command convenience methods, deprecated callbacks, consumer adapters,
product records, prompts, missions, approval policy, persistence, and release
authority are outside this contract.
